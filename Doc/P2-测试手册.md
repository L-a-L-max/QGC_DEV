# P2 测试手册 — DDS Typed Readers 与数据流

## 测试环境要求

| 项目 | 要求 |
|------|------|
| 电脑 A | 编译运行 QGC（DDS_P2 分支） |
| 电脑 B | PX4 SITL + MicroXRCE-DDS Agent |
| CycloneDDS | ≥ 0.10.x（电脑 A 上 `/usr/local/lib/libddsc.so`） |
| idlc | ≥ 0.10.x（电脑 A 上 `/usr/local/bin/idlc`） |
| 网络 | 电脑 A 和 B 在同一 DDS domain（默认 domain 0） |
| PX4 版本 | v1.17.0-alpha1 或兼容版本 |
| ROS2 | Humble（电脑 B 上用于验证话题） |

## 前置步骤

### 步骤 0：编译 QGC（电脑 A）

```bash
cd ~/QGC_DDS/qgc_dev
git pull origin DDS_P2

rm -rf build && mkdir build && cd build
cmake .. -G Ninja \
    -DCMAKE_BUILD_TYPE=Debug \
    -DCMAKE_PREFIX_PATH=$QT_DIR \
    -DCMAKE_C_COMPILER=gcc-13 \
    -DCMAKE_CXX_COMPILER=g++-13 \
    -DQGC_ENABLE_DDS=ON
ninja -j$(nproc)
```

**预期输出**（cmake 阶段）：
```
-- Found idlc: /usr/local/bin/idlc
-- CycloneDDS found in prefix: /usr/local
```

**预期输出**（编译阶段）：
```
idlc: Generating VehicleAttitude.h/.c from VehicleAttitude.idl
idlc: Generating BatteryStatus.h/.c from BatteryStatus.idl
... (20 个话题)
[100%] Built target QGroundControl
```

### 步骤 1：启动 PX4 SITL（电脑 B）

```bash
cd ~/PX4-Autopilot
make px4_sitl gz_x500
```

### 步骤 2：启动 DDS Agent（电脑 B）

```bash
MicroXRCEAgent udp4 -p 8888
```

### 步骤 3：验证 DDS 话题可见（电脑 A）

```bash
ros2 topic list
```

**预期**：看到 `/fmu/out/vehicle_attitude`、`/fmu/out/battery_status` 等话题。

## 测试用例

### T01：IDL 代码生成验证

**目的**：确认 idlc 正确生成了所有 20 个类型。

**步骤**：
1. 编译成功后检查生成目录

```bash
ls build/dds_generated/*.h | wc -l
ls build/dds_generated/*.c | wc -l
```

**预期**：各 20 个文件。

**验证**：
```bash
head -5 build/dds_generated/VehicleAttitude.h
```
应包含 `px4_msgs_msg_VehicleAttitude` 结构体定义。

---

### T02：类型注册表初始化

**目的**：确认 DDSTypeRegistry 正确注册了 20 个类型。

**步骤**：
1. 启动 QGC
2. 创建 DDS 链路

**预期日志**：
```
[DDSTypeRegistry] Registered 20 IDL types
```

**失败诊断**：如果数量 < 20，检查 IDL 文件是否完整。

---

### T03：Typed Reader 创建

**目的**：确认为所有映射话题创建了真正的 DDS reader。

**步骤**：
1. 启动 PX4 SITL（电脑 B）
2. 启动 DDS Agent（电脑 B）
3. 启动 QGC（电脑 A）
4. 创建 DDS 链路并连接

**预期日志**：
```
[DDSLink] Loaded mapping: _default topics: 20 fields: 66
[DDSLink] Created DDS participant on domain 0 entity: XXX
[DDSLink] Subscribed: 20 typed readers, 0 stubs, of 20 topics
[DDSLink] DDS link connected on domain 0
```

**关键检查**：
- typed readers 应为 20
- stubs 应为 0
- 如果 typed readers < 20，检查日志中的 `dds_create_topic failed` 或 `dds_create_reader failed` 错误

**启用详细日志**：
```bash
export QT_LOGGING_RULES="Comms.DDSLink.debug=true"
./QGroundControl
```

---

### T04：DDS Vehicle 自动创建

**目的**：确认纯 DDS 模式下 Vehicle 对象被自动创建。

**步骤**：
1. 确保 PX4 SITL 正在运行（电脑 B）
2. 启动 QGC，创建 DDS 链路并连接
3. 等待数据接收

**预期日志**：
```
[DDSVehicleManager] Creating DDS vehicle: id= 1 type= 1 MAV_TYPE= 2
[DDSVehicleManager] Attached DDSDataInjector to vehicle 1
```

**预期 UI 现象**：
- QGC 界面从"未连接"状态变为显示飞行器
- 飞行器工具栏出现
- Vehicle 状态指示器显示

**失败诊断**：
- 如果没有 "Creating DDS vehicle" 日志：vehicle_status 话题没有收到数据
  - 检查 `ros2 topic echo /fmu/out/vehicle_status`（电脑 A）
  - 检查 DDS domain ID 是否匹配
- 如果 "Vehicle not found"：MultiVehicleManager 拒绝了创建请求
  - 可能是 vehicle ID 冲突（已存在 ID=1 的 MAVLink vehicle）

---

### T05：姿态数据显示

**目的**：验证 vehicle_attitude 数据正确注入到 QGC 姿态仪表。

**步骤**：
1. 完成 T04（Vehicle 已创建）
2. 在电脑 B 上使用 PX4 控制台改变飞行器姿态：
   ```
   commander takeoff
   ```
3. 观察 QGC 界面

**预期现象**：
- 姿态球（Attitude Indicator）显示当前 Roll/Pitch
- Heading 指示器更新
- 数据刷新流畅（约 50-100 Hz）

**验证方法**：
```bash
# 电脑 A 上同时查看原始 DDS 数据
ros2 topic echo /fmu/out/vehicle_attitude --field q
```
对比 QGC 显示的角度值应一致（四元数 → 欧拉角变换后）。

---

### T06：GPS/位置数据显示

**目的**：验证地图上显示飞行器位置。

**步骤**：
1. 完成 T05（飞行器已起飞）
2. 观察 QGC 地图

**预期现象**：
- 地图上出现飞行器图标
- 图标位置对应 SITL 仿真位置
- 图标跟随飞行器运动

**验证方法**：
```bash
ros2 topic echo /fmu/out/vehicle_global_position --field lat --field lon
```
对比 QGC 地图上显示的坐标。

---

### T07：电池数据显示

**目的**：验证电池遥测数据。

**步骤**：
1. Vehicle 已连接
2. 查看 QGC 顶部工具栏的电池信息

**预期现象**：
- 电池电压显示（应约 11-16V 范围）
- 电池剩余百分比显示
- 电池电流显示

**验证方法**：
```bash
ros2 topic echo /fmu/out/battery_status --field voltage_v --field remaining
```

---

### T08：飞行模式与解锁状态

**目的**：验证 vehicle_status 数据正确显示。

**步骤**：
1. Vehicle 已连接
2. 在 PX4 控制台切换模式：
   ```
   commander mode manual
   commander mode posctl
   commander mode auto:loiter
   ```
3. 解锁/锁定：
   ```
   commander arm
   commander disarm
   ```

**预期现象**：
- QGC 工具栏显示当前飞行模式文字
- 解锁状态正确反映（Armed/Disarmed）

---

### T09：地速与爬升率

**目的**：验证从 vehicle_local_position 计算的速度数据。

**步骤**：
1. 飞行器已起飞
2. 让飞行器运动（使用 mission 或手动控制）

**预期现象**：
- 地速数值更新（单位 m/s）
- 爬升率数值更新（climb rate）

**数据来源**：
- `ground_speed` = sqrt(vx² + vy²)（变换 `ground_speed_from_vxy`）
- `climb_rate` = -vz（变换 `negate`，NED 坐标系 z 轴向下）

---

### T10：断开与重连

**目的**：验证 DDS 链路断开和重连的稳定性。

**步骤**：
1. 正常连接状态
2. 在 QGC 中断开 DDS 链路
3. 等待 5 秒
4. 重新连接

**预期**：
- 断开时日志显示 `[DDSLink] DDS link disconnected`
- 重新连接后数据恢复
- 无内存泄漏或崩溃

---

### T11：DDS Agent 中断恢复

**目的**：验证 DDS Agent 掉线后的行为。

**步骤**：
1. 正常连接状态
2. 停止电脑 B 上的 DDS Agent（Ctrl+C）
3. 等待 10 秒
4. 重启 DDS Agent

**预期**：
- QGC 数据停止更新（但不崩溃）
- DDS Agent 重启后数据可能自动恢复（取决于 DDS discovery 超时设置）
- 如果数据不恢复，断开重连 DDS 链路即可

## 故障排除

### 编译问题

| 错误 | 原因 | 解决方案 |
|------|------|---------|
| `idlc: command not found` | idlc 未安装 | `cmake -DBUILD_IDLC=ON` 重编 CycloneDDS |
| `dds/dds.h: No such file` | CycloneDDS 头文件路径错误 | `-DCYCLONEDDS_ROOT=/usr/local` |
| C/C++ PCH 冲突 | 生成的 .c 文件加入主目标 | 检查 `dds_idl_types` 静态库是否正确构建 |

### 运行问题

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| typed readers = 0 | DDSTypeRegistry 未找到类型 | 检查 `_default.json` 中的 `dds_type` 字段是否匹配 |
| 有 reader 但无数据 | DDS 类型不匹配 | 检查 IDL 定义是否与 PX4 版本一致 |
| Vehicle 未创建 | vehicle_status 未收到 | 检查 DDS 网络连通性 |
| 数据刷新慢 | 网络延迟或 poll interval | 检查 `_pollTimer.setInterval()` 值 |

### 日志级别

| 环境变量 | 效果 |
|----------|------|
| `QT_LOGGING_RULES="Comms.DDSLink.debug=true"` | 显示每个 reader 创建和数据读取详情 |
| 无需设置 | `[DDSLink]` 前缀的 qInfo 日志始终可见 |
