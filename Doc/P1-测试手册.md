## 1. 测试环境概述

| 设备 | 角色 | 说明 |
|------|------|------|
| 电脑 A（你的工作站） | QGC 运行端 | 编译并运行 QGC（DDS_P1 分支），能通过 `ros2 topic list` 看到话题 |

### 2.2 QML 设置页面错误

```
161.231 DDSSettings.qml:60: TypeError: Cannot read property 'autoDiscover' of null
161.232 DDSSettings.qml:48: TypeError: Cannot read property 'namespacePrefix' of null
161.232 DDSSettings.qml:35: TypeError: Cannot read property 'vendorMapping' of null
161.232 DDSSettings.qml:21: TypeError: Cannot read property 'domainId' of null
```

**原因：** DDSSettings.qml 页面的 `subEditConfig` 属性为 null。这是在未先创建 DDS 链路配置的情况下直接打开设置页面导致的。这是一个 **非阻断性的 UI 初始化顺序问题**，不影响核心 DDS 功能。

### 2.3 为什么看不到更多 DDS 日志

DDSLink 的日志使用 Qt 分类日志系统（`QGC_LOGGING_CATEGORY(DDSLinkLog, "Comms.DDSLink")`）。
默认情况下，`qCDebug` 级别的分类日志不会显示。

**启用详细日志方法：**

```bash
# 方法1：环境变量
export QT_LOGGING_RULES="Comms.DDSLink.debug=true"
./QGroundControl

# 方法2：在 QGC 内部
# 设置 → 控制台 → 选择 "Comms.DDSLink" 日志分类
```

启用后应该能看到：
```
DDSLink created
Created DDS participant on domain 0 entity: XXX
Registered topic: rt/fmu/out/vehicle_attitude (reader pending type support)
Registered 20 of 20 topics (type support pending)
DDS link connected on domain 0
```

### 2.4 为什么界面没有显示连接成功

**这是 P1 版本的预期行为。** 原因链：

1. P1 版本的 `_subscribeToTopics()` 注册了话题名，但没有创建实际的 DDS typed reader
2. `_readSample()` 始终返回空（无类型描述符，无法反序列化 DDS 数据）
3. 因此 `ddsMessageReceived` 信号从不发射
4. DDSDataInjector 不会收到任何数据
5. 没有数据注入到 QGC 的 Fact 系统
6. QGC 界面不会显示遥测数据

**重要说明：** QGC 的 Vehicle 对象由 MAVLink heartbeat 创建，不由 DDS 创建。DDS 是**补充数据源**，而非替代 MAVLink。在当前架构中：
- MAVLink：发现和管理飞行器（heartbeat → Vehicle 对象）
- DDS：高速注入遥测数据到已有 Vehicle 的 Fact 系统

## 4. 详细测试步骤

### 测试 T01：编译验证

**目的：** 确认 DDS 功能正确编译到 QGC 二进制文件中

**步骤：**
```bash
cd ~/QGC_DDS/qgc_dev
git pull origin DDS_P1
rm -rf build && mkdir build && cd build
cmake .. -G Ninja \
    -DCMAKE_BUILD_TYPE=Debug \
    -DCMAKE_PREFIX_PATH=$QT_DIR \
    -DCMAKE_C_COMPILER=gcc-13 \
    -DCMAKE_CXX_COMPILER=g++-13 \
    -DQGC_ENABLE_DDS=ON
ninja -j$(nproc)
```

**预期结果：**
- cmake 输出包含 `-- Found CycloneDDS: /usr/local/lib/libddsc.so`
- ninja 编译成功，无错误
- 生成 `build/Debug/QGroundControl` 可执行文件

**通过标准：** 编译零错误

### 测试 T03：DDS Participant 创建

**目的：** 验证 CycloneDDS participant 能在指定 domain 上正确创建

**步骤：**
```bash
# 启用 DDS 详细日志
export QT_LOGGING_RULES="Comms.DDSLink.debug=true"
cd build/Debug
./QGroundControl 2>&1 | tee /tmp/qgc_dds_test.log
```

在 QGC 中：
1. 打开 **Application Settings → Comm Links**
2. 点击 **Add** 添加新链路

5. Domain ID 设为 `0`（匹配 PX4 默认 domain）

7. Namespace Prefix 留空
8. 点击 **OK** 保存
9. 选择刚创建的 `PX4_DDS` 链路
10. 点击 **Connect**

**预期日志：**

## 7. 已知限制（P1 → P2 过渡）

| 限制 | 原因 | P2 解决方案 |
|------|------|-------------|
| 无法读取 DDS 话题数据 | 缺少 IDL 类型描述符 | 从 PX4 msg 定义生成 CycloneDDS 类型（idlc） |
| 界面无遥测显示 | 无数据注入到 Fact | 实现 typed reader + 数据解析 |
| DDSSettings.qml null 错误 | 打开设置时 config 未初始化 | 修复 QML 绑定时机 |
| DDS 不创建 Vehicle | QGC 架构限制 | DDS 作为补充数据源附加到 MAVLink Vehicle |

## 8. 故障排查

### 问题：编译时 `CycloneDDS::ddsc does not exist`
**原因：** CMake 找到的 CycloneDDS 版本不一致（ROS2 vs /usr/local）
**解决：**
```bash
cmake .. -DCYCLONEDDS_ROOT=/usr/local ...
```

### 问题：日志无 DDS 相关输出
**原因：** Qt 分类日志默认关闭 debug 级别
**解决：**
```bash
export QT_LOGGING_RULES="Comms.DDSLink.debug=true"
```

### 问题：DDS participant 创建失败
**可能原因：**
- CycloneDDS 动态库路径不在 LD_LIBRARY_PATH
- DDS domain ID 与网络配置冲突
**解决：**
```bash
export LD_LIBRARY_PATH=/usr/local/lib:$LD_LIBRARY_PATH
```

### 问题：`ros2 topic list` 可见但 QGC DDS 无反应
**这是 P1 预期行为。** P1 仅创建 participant，不创建 typed reader。数据读取将在 P2 实现。
