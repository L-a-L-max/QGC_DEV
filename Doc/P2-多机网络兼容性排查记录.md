| 项目 | 内容 |
|------|------|
| 状态 | **封存** — 待网络层面进一步排查 |

## 排查步骤与结果

### 第 1 步：QGC SPDP 组播是否发出

**测试命令**（ucs-node）：
```bash
sudo tcpdump -i eno3np2 src host 192.168.80.155 and dst host 239.255.0.1 -c 5
```

**结果**：✅ 正常发出
```
ucs-node.34249 > 239.255.0.1.7400: UDP, length 412  (每 8 秒一次)
```

### 第 2 步：PX4 是否收到 QGC 的 SPDP

**测试命令**（ucs-master）：
```bash
sudo tcpdump -i ens33 dst host 239.255.0.1 and src host 192.168.80.155 -c 5
```

**结果**：✅ PX4 收到 QGC 的组播
```
192.168.80.155.34249 > 239.255.0.1.7400: UDP, length 412
```

### 第 3 步：PX4 是否向 QGC 发送单播响应

**测试命令**（ucs-node）：
```bash
sudo tcpdump -i eno3np2 src host 192.168.80.11 and dst host 192.168.80.155 and udp -c 10
```

**结果**：✅ PX4 有向 QGC 发送单播
```
192.168.80.11.49953 > ucs-node.38851: UDP, length 112  (HEARTBEAT)
192.168.80.11.49953 > ucs-node.38851: UDP, length 708  (SPDP 单播响应)
```

**分析**：PX4 发现了 QGC 参与者，向其发送 HEARTBEAT。

### 第 4 步：QGC 是否在监听正确端口

**测试命令**（ucs-node）：
```bash
ss -ulnp | grep -i qground
```

**结果**：✅ QGC 在监听 port 38851
```
UNCONN 0 0 0.0.0.0:38851 users:(("QGroundControl",...,fd=47))
```

### 第 5 步：QGC 是否向 PX4 发送 ACKNACK

**测试命令**（ucs-node）：
```bash
sudo tcpdump -i eno3np2 src host 192.168.80.155 and dst host 192.168.80.11 and udp -c 10
```

**结果**：✅ QGC 有发出 ACKNACK
```
ucs-node.53942 > 192.168.80.11.7410: UDP, length 64   (ACKNACK)
ucs-node.53942 > 192.168.80.11.7410: UDP, length 280  (SPDP/其他)
```

### 第 6 步：重启 PX4 Agent

**操作**：停掉成功机器 QGC，只保留失败机器运行，重启 PX4 Agent。

**结果**：❌ 仍然无法连接

### 第 7 步：清空 iptables

**测试命令**（ucs-node）：
```bash
sudo iptables -F && sudo iptables -t nat -F && sudo iptables -t mangle -F && sudo iptables -t raw -F
```

**结果**：❌ 清空所有防火墙后仍然无法连接

### 第 8 步：从 PX4 端抓取发往失败机器的所有流量

**测试命令**（ucs-master）：
```bash
sudo tcpdump -i ens33 dst host 192.168.80.155 -c 30 -nn
```

**结果**：⚠️ PX4 **只发送 HEARTBEAT 和 SPDP，从未发送 SEDP DATA**
```
所有包只有 112 字节 (HEARTBEAT) 和 708 字节 (SPDP)
没有 >1000 字节的 SEDP DATA 包
```

**关键结论**：PX4 反复发送 HEARTBEAT（"我有数据"），但从未发送实际的 SEDP 发布数据。这说明 PX4 没有收到或没有正确处理 QGC 的 ACKNACK（"请给我数据"）。

### 第 9 步（未完成）：确认 ACKNACK 是否到达 PX4

**计划测试**（ucs-master）：
```bash
sudo tcpdump -i ens33 src host 192.168.80.155 and udp -c 10 -nn
```

**目的**：确认 QGC 发出的单播 ACKNACK 是否实际到达 PX4 机器。

**状态**：问题封存，未执行此步骤。

## 已排除的原因

| 排除项 | 证据 |
|--------|------|
| 代码问题 | 同一代码在 ros2-0 上正常工作 |
| iptables/防火墙 | 全部清空后仍然无法连接 |
| eBPF/TC 过滤器 | `tc filter show` 为空 |
| CNI/Calico/Cilium | 未安装 |
| XDP 程序 | 网卡上无 XDP |
| 组播不通 | 双向组播正常 |
| 单播不通（PX4→QGC） | tcpdump 确认 HEARTBEAT 到达 |
| QGC 未监听 | ss 确认 socket 绑定正确 |
| 内核缓冲区差异 | 两台机器 rmem_max 相同 (212992) |
| ROS2 daemon 冲突 | 停掉 daemon 后问题依旧 |
| PX4 多订阅者限制 | 单独运行失败机器仍然失败 |

## 问题本质

```
QGC (CycloneDDS)                    PX4 Agent (FastDDS)
     |                                      |
     |--- SPDP (multicast) ------→         | ✅ PX4 收到
     |                                      |
     |         ←------ SPDP (unicast) -----| ✅ QGC 收到
     |                                      |
     |         ←------ HEARTBEAT ----------| ✅ QGC 收到 (112 bytes)
     |                                      |
     |--- ACKNACK (unicast) ------→        | ❓ 可能未到达 PX4
     |                                      |
     |         ←------ DATA ??? -----------| ❌ 从未发送
     |                                      |
```

**最可能的根因**：QGC 的 ACKNACK 单播包离开了 ucs-node 的 eno3np2 接口（tcpdump 确认），但**未能到达 PX4 的 ens33 接口**。中间网络路径（交换机、路由器）可能对来自 192.168.80.155 的特定单播 UDP 做了丢弃或过滤。

## 两台机器的环境差异

| 对比项 | ros2-0 (成功) | ucs-node (失败) |
|--------|---------------|-----------------|
| iptables | 无任何规则 | 有 Kubernetes 规则（KUBE-FIREWALL 等） |
| Kubernetes | 未安装 | 安装（作为 worker node） |
| 主机名 | ros2-0 | ucs-node |
| ROS2 daemon | 无 | 有（rmw_fastrtps_cpp） |
| 物理网卡 | 待确认 | eno3np2 (192.168.80.155) |

## 后续排查建议

1. **确认 ACKNACK 是否到达 PX4**（第 9 步）：
   ```bash
   # 在 PX4 机器上
   sudo tcpdump -i ens33 src host 192.168.80.155 and udp -c 10 -nn
   ```
   如果只看到组播（dst 239.255.0.1）没有单播（dst 192.168.80.11），则确认是网络中间设备丢弃了单播。

2. **检查交换机 MAC 地址表/ARP**：
   ```bash
   # ucs-node 上
   arp -n | grep 192.168.80.11
   ip neigh show 192.168.80.11
   ```
   确认 ucs-node 有正确的 ARP 映射到 PX4 机器。

3. **检查路由表**：
   ```bash
   ip route get 192.168.80.11
   ```
   确认单播到 192.168.80.11 走 eno3np2 而非其他接口。

4. **尝试设置固定 ParticipantIndex**：修改 CycloneDDS 配置使用标准端口（如 7414/7415），避免随机端口可能触发的网络设备策略。

5. **对比网卡 offload 设置**：
   ```bash
   ethtool -k eno3np2 | grep -E "udp|gro|gso|tso"
   ```

使用 ros2-0 机器运行 QGC（确认可正常连接），将 ucs-node 的网络问题作为独立基础设施问题处理。
