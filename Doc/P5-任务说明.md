## 二、P5 目标

**核心目标**：实现从"单点飞行"到"多点任务"的跨越。

用户能够：
1. 在地图上规划多个航点（含速度、高度、航向）
2. 一键执行航点任务，无人机自动逐点飞行
3. 飞行过程中可暂停/继续/修改
4. 虚拟摇杆可配置最大速度

## 三、P5 功能清单

### 模块 A：虚拟摇杆增强（⭐ 小工作量）

| 功能 | 说明 |
|------|------|
| **最大速度配置** | 设置页增加"最大飞行速度"滑块（1~20 m/s），摇杆值按比例缩放 |
| **死区配置** | 摇杆中心区域不响应（避免误触），默认 5%，可调 |
| **灵敏度曲线** | 线性/指数曲线可选，指数曲线在低速区更精细 |

**实现方式**：
- QGC Settings 新增 Fact（存储到 QSettings）
- `DDSManualControlPublisher::sendManualControl()` 中应用缩放
- 不依赖 PX4 参数，纯 QGC 端配置

---

### 模块 B：GotoSetpoint 精确指点飞行（⭐⭐ 中工作量）

**为什么需要**：当前 Go To 使用 `MAV_CMD_DO_REPOSITION`（VehicleCommand），这是 MAVLink 命令方式。PX4 DDS 原生提供了 `fmu/in/goto_setpoint`（GotoSetpoint 消息），优势：

| 对比 | DO_REPOSITION | GotoSetpoint |
|------|--------------|-------------|
| 速度控制 | 无（使用默认巡航速度） | ✅ `max_horizontal_speed`, `max_vertical_speed` |
| 航向控制 | 有限（弧度参数） | ✅ `heading` + `flag_control_heading` |
| 航向速率限制 | 无 | ✅ `max_heading_rate` |
| 坐标系 | 经纬度 (WGS84) | NED 本地坐标（需转换） |
| 用途 | 单次定位 | 连续逐点导航 |

**GotoSetpoint 消息定义**（PX4）：
```
float32[3] position          # [m] NED 本地坐标
bool flag_control_heading    # 是否控制航向
float32 heading              # [rad] 目标航向
bool flag_set_max_horizontal_speed
float32 max_horizontal_speed # [m/s] 水平速度限制
bool flag_set_max_vertical_speed
float32 max_vertical_speed   # [m/s] 垂直速度限制
bool flag_set_max_heading_rate
float32 max_heading_rate     # [rad/s] 航向变化速率限制
```

**实现内容**：
1. 新增 `GotoSetpoint.idl`
2. 新增 `DDSGotoPublisher`（发布 GotoSetpoint 消息）
3. 经纬度 → NED 坐标转换（以 Home 位置为原点）
4. QGC 飞行界面 "Go To" 操作可选择使用 GotoSetpoint 路径

### 模块 C：简易航点任务规划（⭐⭐⭐ 核心功能）

**设计思路**：不走 MAVLink Mission Protocol（PX4 DDS 不支持），而是用 **GotoSetpoint 逐点导航** 实现。

#### 用户交互流程

```
1. 进入规划界面（PlanView 或简化版）
2. 在地图上依次点击添加航点
3. 每个航点可设置：
   - 高度 (m)
   - 速度 (m/s)
   - 航向 (°，可选)
   - 悬停时间 (s，可选)
4. 点击 "开始任务"
5. QGC 自动逐点发送 GotoSetpoint
6. 到达每个航点后自动前进到下一个
7. 全部完成后自动悬停（或 RTL）
```

#### 技术架构

```
┌─────────────────────────────────────┐
│ QGC 任务管理器 (DDSMissionManager)   │
│                                     │
│  航点列表:                           │
│  [WP1: lat,lon,alt,spd,hdg,hover]  │
│  [WP2: lat,lon,alt,spd,hdg,hover]  │
│  [WP3: lat,lon,alt,spd,hdg,hover]  │
│                                     │
│  状态机:                             │
│  IDLE → RUNNING → WP1 → WP2 → ... → COMPLETE │
│         ↕ PAUSED                    │
└──────────────┬──────────────────────┘
               │ 当前航点
               ▼
┌──────────────────────────────────────┐
│ DDSGotoPublisher                     │
│  → 发布 GotoSetpoint (NED + 速度约束) │
│  → 话题: fmu/in/goto_setpoint        │
└──────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────┐
│ PX4 Position Controller              │
│  → 平滑飞向目标点                     │
│  → 到达判定 → QGC 切换下一航点        │
└──────────────────────────────────────┘
```

#### 航点到达判定

订阅 `fmu/out/vehicle_global_position`，计算当前位置与目标航点的距离：
- 水平距离 < 2m 且 垂直距离 < 1m → 视为到达
- 如有悬停时间，等待指定时间后前进到下一航点

#### 航点数据模型

```cpp
struct DDSWaypoint {
    double latitude;       // 纬度
    double longitude;      // 经度
    float  altitude;       // 相对高度 (m)
    float  speed;          // 最大飞行速度 (m/s), 0=使用默认
    float  heading;        // 目标航向 (°), NaN=不控制
    float  hoverTime;      // 到达后悬停时间 (s), 0=不悬停
};
```

#### 任务保存/加载

支持 JSON 格式保存和加载航点列表：
```json
{
  "version": 1,
  "waypoints": [
    {"lat": 47.3977, "lon": 8.5456, "alt": 10, "speed": 5, "heading": 90, "hover": 3},
    {"lat": 47.3980, "lon": 8.5460, "alt": 15, "speed": 8, "hover": 0},
    {"lat": 47.3975, "lon": 8.5450, "alt": 10, "speed": 3, "heading": 0, "hover": 5}
  ],
  "endAction": "hover"
}
```

### 模块 D：Offboard 模式轨迹控制（⭐⭐ 可选/高级）

使用 `fmu/in/trajectory_setpoint` + `fmu/in/offboard_control_mode` 实现更精确的轨迹跟踪。

**与 GotoSetpoint 的区别**：

| 对比 | GotoSetpoint | TrajectorySetpoint |
|------|-------------|-------------------|
| 控制方式 | 给目标点，PX4 自主规划路径 | 给瞬时位置/速度/加速度，QGC 完全控制 |
| 平滑度 | PX4 内置平滑器 | 需要 QGC 端实现插值 |
| 发送频率 | 低频（到达后发下一个） | 高频（>10Hz 持续发送） |
| 适用场景 | 航点导航 | 精确轨迹跟踪、编队飞行 |
| PX4 模式 | 自动进入导航模式 | 需要 Offboard 模式 |
| 复杂度 | ⭐⭐ | ⭐⭐⭐⭐ |

**建议**：P5 先用 GotoSetpoint 实现航点导航，TrajectorySetpoint 作为 P6/P7 的高级功能。

## 四、UI 方案选择

### 方案 A：复用原版 PlanView（改造成本高）

原版 QGC 的 PlanView 深度耦合 MAVLink Mission Protocol（MissionItem → MissionManager → MAVLink MISSION_ITEM_INT）。改造需要：
- 替换 MissionManager 的上传/下载逻辑
- 保留 PlanView 的地图交互 UI
- 工作量大，但 UI 成熟

### 方案 B：新建简易规划界面（推荐）

新建一个 `DDSPlanView.qml`，只包含：
- 地图上点击添加航点
- 航点列表（可编辑高度/速度/航向/悬停时间）
- 开始/暂停/停止按钮
- 航点到达进度显示

优点：不改动原有代码，独立清晰。
缺点：不支持 Survey/走廊扫描等复杂任务。

### 方案 C：飞行界面内嵌（最小化）

不新建规划页面，直接在飞行界面添加：
- 长按地图添加航点（类似 Go To，但可以连续添加多个）
- 底部显示航点列表
- 一键执行

最简单，但功能有限。

```
P5-3: DDSMissionManager 航点状态机                ← 2-3 天
P5-4: 简易航点规划 UI (方案 B 或 C)               ← 3-5 天
P5-5: 任务保存/加载 (JSON)                        ← 1 天
P5-6: 测试验证 + 文档                             ← 1-2 天
```

**总预估**：10-15 天
