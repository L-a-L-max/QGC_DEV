# P4 — DDS 多机支持测试方案

## 1. 测试环境准备

### 1.1 硬件/软件要求

| 项目 | 要求 |
|------|------|
| QGC 机器 | ros2-0（编译 DDS_P4 分支） |
| PX4 机器 | 至少 2 台运行 PX4 SITL 或实机，每台配置不同 namespace |
| 网络 | 同一局域网，组播可达 |
| PX4 版本 | v1.17.0-alpha1（与 P2/P3 相同） |

### 1.2 PX4 Namespace 配置

**飞机 1（ros2-0 或其他机器）：**
```bash
# 在 PX4 终端
param set UXRCE_DDS_NS drone1
param save
# 重启 XRCE-DDS Agent
```

**飞机 2（另一台机器或同机不同实例）：**
```bash
param set UXRCE_DDS_NS drone2
param save
```

验证 namespace 生效：
```bash
# 在任意 ROS2 环境
ros2 topic list | grep drone
# 应看到:
# /drone1/fmu/out/vehicle_status_v1
# /drone2/fmu/out/vehicle_status_v1
```

## 2. 测试用例

### 2.1 Namespace 自动发现

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | QGC → 应用设置 → Comm Links → Add | 进入连接配置页面 |
| 2 | 选择连接类型为 DDS | 显示 DDS 设置界面 |
| 3 | 填写 Domain ID 为 0 | Domain ID 输入框显示 0 |
| 4 | 点击"扫描"按钮 | 按钮变为加载状态 |
| 5 | 等待 3-5 秒 | 下拉列表显示发现的 namespace（如 drone1, drone2） |
| 6 | 下拉列表可选择 drone1 | namespace 字段更新为 "drone1" |

### 2.2 手动输入 Namespace

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 在 namespace 下拉列表中直接输入 "custom_ns" | 输入框接受自定义文本 |
| 2 | 点击 Save | 配置保存成功 |
| 3 | 连接 | DDSLink 订阅 rt/custom_ns/fmu/out/* 话题 |

### 2.3 单机连接（指定 Namespace）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 创建 DDS 连接，namespace = drone1 | 连接配置保存 |
| 2 | 启动连接 | QGC 只订阅 rt/drone1/fmu/out/* |
| 3 | 观察 QGC 主界面 | 显示 drone1 的飞行数据 |
| 4 | 点击起飞 | drone1 起飞（drone2 不受影响） |
| 5 | 点击 RTL | drone1 返航 |
| 6 | 查看日志 | 命令发送到 rt/drone1/fmu/in/vehicle_command |

### 2.4 双机同时连接

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 创建 DDS 连接 1，namespace = drone1 | 配置保存 |
| 2 | 创建 DDS 连接 2，namespace = drone2 | 配置保存 |
| 3 | 同时连接两个链接 | 两架飞机同时出现在 QGC 中 |
| 4 | 选择 drone1，发送起飞命令 | 只有 drone1 起飞 |
| 5 | 选择 drone2，发送起飞命令 | 只有 drone2 起飞 |
| 6 | 向 drone1 发送 RTL | 只有 drone1 返航 |

### 2.5 向后兼容（无 Namespace）

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 创建 DDS 连接，namespace 留空 | 配置保存 |
| 2 | PX4 未设置 UXRCE_DDS_NS（默认） | topic 为 rt/fmu/out/* |
| 3 | 连接 | 行为与 P3 完全一致 |
| 4 | 起飞/降落/RTL | 全部正常工作 |

### 2.6 错误 Domain ID

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 填写 Domain ID 为 99（PX4 使用 0） | 不同域 |
| 2 | 点击"扫描" | 无法发现任何 namespace |
| 3 | 等待超时 | 下拉列表为空，显示提示信息 |

### 2.7 发现过程中 PX4 上线

| 步骤 | 操作 | 预期结果 |
|------|------|---------|
| 1 | 先点击"扫描"（此时无 PX4） | 下拉列表为空 |
| 2 | 启动 PX4（带 namespace） | 3-5 秒后下拉列表自动更新 |
| 3 | 选择新发现的 namespace | 可以正常选择 |

## 3. 验证检查点

### 3.1 日志关键字

| 日志内容 | 含义 |
|---------|------|
| `[DDSDiscovery] Started discovery on domain X` | 发现开始 |
| `[DDSDiscovery] Found namespace: droneX` | 发现新 namespace |
| `[DDSDiscovery] Discovery complete: N namespaces` | 发现结束 |
| `[DDSLink] Subscribed: N typed readers` | 创建了 N 个 reader |
| `[DDSCommandPublisher] Writer created for topic: rt/droneX/fmu/in/vehicle_command` | 命令通道建立 |

### 3.2 数据隔离验证

- drone1 的 GPS 数据不应出现在 drone2 的 QGC 面板中
- 向 drone1 发送的命令不应被 drone2 收到
- 断开 drone1 连接不影响 drone2

## 4. 已知限制

1. **PX4 必须配置 namespace** — 如果多架 PX4 没有配置不同 namespace，它们的 topic 会重叠
2. **需要相同 Domain ID** — QGC 和 PX4 必须在同一个 DDS Domain 中
3. **发现依赖组播** — 如果网络不支持组播，发现功能无法工作
4. **Vehicle ID** — 多机场景下 Vehicle ID 自动分配，不与 MAVLink 系统的 sysid 一一对应
